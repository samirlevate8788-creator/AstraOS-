AstraOS Documentation

Boot the published AstraOS 0.1.1 image, build the newer 0.2.0-alpha security-learning source, or follow the safe lab guide.

Download v0.1.1Build from source

Boot the live system

  1. Download AstraOS-0.1.1-amd64.iso and its SHA-256 file.
  2. Verify the ISO checksum before writing it.
  3. Write the ISO to an 8 GB or larger USB drive with an image-writing utility. This erases the selected USB drive.
  4. Restart and choose the USB drive in the PC's firmware boot menu.
  5. If UEFI refuses to start the unsigned bootloader, disable Secure Boot in firmware and try again.

The BIOS and UEFI paths have reached the live desktop in QEMU/KVM, and the XFCE terminal opened successfully. AstraOS runs as a live session and does not install onto the internal drive. Physical PC compatibility still needs testing.

Build from source on Ubuntu or WSL

The current development recipe builds a separate 0.2.0-alpha amd64 image with the ethical security learning tools.

sudo apt update
sudo apt install --yes debian-archive-keyring live-build debootstrap \
  xorriso squashfs-tools grub-pc-bin grub-efi-amd64-bin mtools \
  isolinux rsync cpio git
git clone https://github.com/samirlevate8788-creator/AstraOS-.git
cd AstraOS-
git switch os/v0.1-live-build
cd os
sudo bash ./build.sh

The new ISO and checksum are written to os/dist/ as AstraOS-0.2.0-alpha-amd64.iso. This development build has not been released or hardware-validated. The existing v0.1.1 download remains unchanged. The build needs network access to Debian mirrors and several gigabytes of free space.

Build layout

Packages

os/config/package-lists/ selects the desktop, browser, defensive security tools and developer packages.

Branding and guide

os/config/includes.chroot/ contains artwork, desktop settings, welcome utility and the offline Ethical Security Lab guide.

Boot image

os/build.sh creates the BIOS and UEFI hybrid ISO and EFI USB partition.

Live release scope

The published v0.1.1 image is a Debian-based live distribution, not a custom kernel or disk installer. Its BIOS and UEFI paths reached the desktop in QEMU/KVM; physical PC compatibility still needs testing. The UEFI loader is unsigned, so Secure Boot may need to be disabled. Security tools described in the Ethical Security Lab are part of the 0.2.0-alpha source work, not this download.

Website deployment notes

The static site upgrades insecure subresources and uses HTTPS canonical URLs. GitHub Pages host settings cannot be changed from repository files: the repository owner still needs to open Settings → Pages and enable Enforce HTTPS. The contact form opens a local email draft instead of posting data to a server, so its honeypot is a basic client-side check, not server-grade spam protection. Optional GA4 stays off until a measurement ID is configured and a visitor accepts analytics.
